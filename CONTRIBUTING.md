# Contributing to QuickShow

Thanks for your interest in contributing to **QuickShow**
This project is built with a focus on real-world architecture, and contributions are always welcome.

---

## How to Contribute

### 1. Fork the Repository

Click on the **Fork** button and create your own copy of the repository.

---

### 2. Clone the Repository

```
git clone https://github.com/baibhavsinhadev/quickshow.git
cd quickshow
```

---

### 3. Create a New Branch

Always create a new branch before making changes.

```
git checkout -b feature/your-feature-name
```

Examples:

* `feature/add-refund-system`
* `fix/seat-selection-bug`
* `improvement/ui-enhancements`

---

### 4. Make Changes

* Follow existing code structure
* Write clean and readable code
* Keep commits small and meaningful

---

### 5. Commit Changes

Use clear commit messages:

```
feat: add refund system
fix: resolve seat booking race condition
refactor: optimize show query logic
```

---

### 6. Push Changes

```
git push origin feature/your-feature-name
```

---

### 7. Create Pull Request

* Go to your forked repo
* Click **New Pull Request**
* Add proper title and description
* Explain what you changed and why

---

## Contribution Guidelines

* Follow the existing folder structure
* Avoid breaking existing functionality
* Test your changes before submitting
* Use meaningful variable and function names
* Keep UI consistent with current design

---

## Reporting Bugs

If you find a bug:

1. Check if it already exists in issues
2. If not, create a new issue with:

   * Clear title
   * Steps to reproduce
   * Expected vs actual behavior

---

## Feature Requests

Want to add something cool?

* Open an issue first
* Explain the feature clearly
* Wait for discussion before implementing (for large features)

---

## Security Issues

If you find any security vulnerability, please report it privately instead of opening a public issue.

---

## Code of Conduct

* Be respectful and constructive
* No toxic or abusive behavior
* Help others grow

---

## Note

This is a **portfolio project**, but built with production-level practices.
So contributions should maintain code quality and system design standards.

---

## Final Words

Every contribution, big or small, matters.

If you're improving QuickShow, you're already doing something valuable 💯
